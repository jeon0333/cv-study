# 학습 안내: 논문을 '읽는 것'에서 '이해하는 것'으로

논문 공부는 요약문을 많이 모으는 일이 아니라, **문제를 스스로 다시 설명하고 필요한 코드를 직접 구현할 수 있는 상태**로 나아가는 과정입니다. 이 사이트는 각 논문을 다음 여섯 단계로 다룹니다.

## 추천 학습 순서

| 단계 | 읽으면서 던질 질문 | 남겨야 할 산출물 |
|---|---|---|
| 1. 문제 | 이전 방법에는 어떤 한계가 있었을까? | 한 문장 문제 정의 |
| 2. 직관 | 저자들은 무엇을 바꾸려 했을까? | 나만의 비유와 설명 |
| 3. 수식 | 각 기호가 의미하는 입력·출력은 무엇일까? | 수식과 shape 노트 |
| 4. 구조 | 다이어그램과 코드의 어느 부분이 대응할까? | 구현과 단위 테스트 |
| 5. 근거 | 어떤 실험이 주장을 지지할까? | 표/그림의 해석 및 한계 |
| 6. 복습 | 논문 없이 설명할 수 있을까? | 확인 문제와 실험 기록 |

## 하루 공부 루틴 예시 (50~70분)

- **10분:** 전날 적은 3줄 요약과 모르는 용어 복습
- **20분:** 해당 단원의 문제와 개념을 읽고 자기 말로 정리
- **20~30분:** 작은 수치 예제, 코드 또는 논문 표 분석
- **10분:** 이해도 문제를 풀고 내일 질문 하나 남기기

소요 시간은 예시입니다. 익숙하지 않은 개념이 나오면 속도를 줄여도 됩니다.

## 독해하기 어렵다면 이 순서로

!!! example "예시: Residual Learning"
    **원문 용어:** *Residual mapping*

    **쉬운 뜻:** 입력에서 최종 출력으로 바뀌어야 할 **차이(변화량)**를 학습한다는 뜻입니다.

    **숫자로 보기:** 입력이 5이고 원하는 출력이 7이면, 전체 7을 바로 만들기보다 2를 배워서 5에 더합니다.

    **한계:** 실제 딥러닝에서는 숫자 하나가 아니라 많은 채널과 위치를 가진 텐서이며, '차이를 배우면 항상 쉽다'라는 정리는 아닙니다.

## 논문 속 문장을 구분해서 읽기

- **관찰:** 논문 표에서 실제 측정된 사실. 예: 34층 plain network의 오류율이 높게 측정됨.
- **저자 가설:** 그런 현상이 발생한 이유에 대한 해석. 예: 잔차 형태가 최적화를 더 쉽게 만들 수 있음.
- **내 결론:** 학습자가 증거를 근거로 이끌어낸 주장. 원문과 구분해서 기록합니다.

## 학습 내용을 얼마나 기억해야 할까?

저장하는 것은 수식 전체가 아니라 **설명할 수 있는 관계**입니다. 다음 질문에 1분 안에 답하면 한 단원을 마쳤다고 볼 수 있습니다.

1. 무슨 문제를 다루는가?
2. 입력과 출력은 무엇인가?
3. 기존 접근보다 달라진 핵심 아이디어는 무엇인가?
4. 어떤 실험이 효과를 보여 주는가?
5. 내 구현은 논문과 무엇이 다른가?

체크리스트는 [학습 진행표](progress.md)에서 관리하세요.
